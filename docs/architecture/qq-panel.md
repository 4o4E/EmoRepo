# QQ 长按表情面板

- 状态：`implemented`
- 日期：2026-08-28

## 目标

EmoRepo 在 Android QQ NT 聊天页提供一条完整且独立于 QAux 的使用链：

```text
长按 QQ“表情”按钮
  → 打开 EmoRepo 底部面板
  → 选择表情包和表情
  → 使用 QQ 当前会话发送原文件
  → QQ 确认成功后记录最近使用并按设置同步
```

图片消息的“添加到 EmoRepo”菜单继续作为反向导入链路；两条链路都只通过受控 IPC 访问 App 私有仓库。

## 入口和兼容

- 短按 QQ“表情”按钮保持 QQ 原行为；只有长按被 EmoRepo 消费。
- 普通私聊、群聊和 QQ NT 群频道使用同一入口；没有当前会话时不打开可发送面板。
- 入口定位参考 QAux 已验证的三组规则：`updateFunBtn`、`mEmojiLayout`、`peerUid + panelCallback`，由 EmoRepo 自己的轻量定位器独立执行。
- 找到候选方法后，必须验证返回值、所属 View 结构和内容描述；最终只给内容描述为“表情”的按钮设置长按监听。
- QQ 重建输入栏时可以重复安装同一个监听；安装必须幂等，短按监听和其他按钮不得改变。
- 定位结果沿用 QQ `versionCode`、APK 指纹和规则版本缓存；多候选、无候选或校验失败时只停用长按入口。

## 当前会话

- 参考 QAux 的 `rootVMBuild` / `recursiveBuildVM` 和 `ChatPie` / `onDestroy` 特征定位会话创建与销毁接点，但不复制其 SessionHooker。
- 会话创建后从 ChatPie 中按类型取得 `AIOParam`，再按 `AIOSession → AIOContact` 结构提取 `chatType`、`peerUid` 和 `guildId`。
- 字段名变化通过结构校验和版本族适配处理，不把每个 QQ 版本单独实现一遍。
- 多个聊天页或浮窗共存时使用栈保存会话；销毁顶层会话后恢复前一个会话。
- 面板打开时冻结一份 Contact 快照；会话销毁、Activity 关闭或 Contact 变化时关闭旧面板，禁止发往错误会话。
- 会话和消息 Contact 必须绑定所属 Activity/ChatPie owner；点击按钮时优先选择同一 Activity 的 SessionEntry。图片消息提取出的 Contact 只允许作为同 Activity 的短期兜底，不能用进程级单值覆盖其他窗口。

## 面板行为

- 使用底部抽屉式的独立 EmoRepo 面板，不替换 QQ 原生表情面板，也不把 EmoRepo 数据伪装成 QQ 收藏表情。
- 面板不显示“EmoRepo 表情”等标题或常驻关闭按钮，只保留顶部拖动把手；系统返回、点击抽屉外区域和抽屉下拉状态负责关闭。
- 抽屉首次打开为约 72% 屏高的收起态，使四列表情区本身接近半屏；用户手指向上滑、开始向下翻找表情时，自动展开到约 92% 屏高，只在顶部保留一小段背景以表达抽屉层级。
- 表情内容始终按 92% 展开高度完成一次测量；收起/展开只动画修改 sheet 的 `translationY`，不能逐帧修改 GridView/ViewPager2 祖先高度。底部表情包栏作为固定覆盖层，不参与 sheet 位移动画；因此状态切换不得触发表情单元格回收、清空 Drawable 或重新提交图片请求。
- 展开态向下拖动时先回到收起态；收起态再次向下拖动才关闭。未达到状态切换阈值时回弹；表情网格未到顶部时，下滑仍只滚动表情列表，把手和标题区域始终可以控制抽屉状态。
- 抽屉底部横向显示表情包栏，方便拇指操作；栏本身使用与抽屉一致的不透明 surface 背景，不能透出下层表情网格。每个入口同时显示封面和名称，封面为 GIF 时自动播放。
- 表情包栏第一项固定为不参与根 `index.jsonl` 排序的虚拟“最近使用”，其后才是根索引顺序。最近使用按协议合并所有设备 CSV，按时间倒序过滤当前已不存在的表情；项仍指向原表情包和原文件，发送后继续更新本设备最近记录。
- QQ 面板过滤 `itemCount == 0` 的真实空表情包，但 Provider 仍向导入目标返回这些可写包；“最近使用”按固定入口规则保留。表情包栏末尾固定齿轮“设置”，点击通过显式 Intent 打开 EmoRepo 软件设置页，不创建一个假的表情包页面。
- 默认选择上次打开的表情包；不存在时选择第一个。切换表情包后回到网格顶部。
- 表情包内容使用横向分页，左右滑动切换相邻表情包；点击顶部表情包入口和滑动翻页保持双向同步。
- 表情网格列数由 EmoRepo App 设置，默认 4，可选 3–8 列；QQ 每次打开面板时通过受控 Provider 读取。单元格高度按可用宽度和列数自动计算为正方形，因此增加列数会同时显示更多表情。静态图和 GIF 都保持宽高比，GIF 自动播放。
- 表情包栏、网格外边距、行列间距和单元格内边距保持紧凑，优先把抽屉高度用于图片内容。
- 元数据分页读取，每页不超过 200 条；图片只加载当前可见区域，快速切包或关闭面板后过期任务只能释放结果。
- 表情单元格回收时必须取消尚未开始的原文件任务；任务开始前和取得租约后都校验单元格代次，已经离屏的任务不得继续占用 FIFO 图片队列。单元格状态使用引用身份管理，不能把含可变加载句柄的 `data class` 放入哈希集合。
- QQ 进程内缓存最近一次面板配置、repository revision、表情包列表和按包分页后的条目元数据，不缓存 Activity、Dialog 或 View。热打开先同步绑定缓存，不显示“正在读取”页面；随后后台查询 Provider 校验配置和 revision，仅在结果变化时原子重建当前面板。
- 普通表情包条目缓存以 `revision + packId` 隔离，revision 变化时清理旧代；“最近使用”在发送成功后直接更新进程内缓存，并在热打开后台重新读取合并 CSV 校正。后台刷新失败但已有缓存时保留旧内容并记录日志，首次无缓存失败时仍显示错误页。
- Provider 不可用、仓库未配置或读取失败时保留错误页，显示精简原因和“重试”，不能静默显示空面板。
- 长按表情后在当前面板内显示非模态大图预览；预览优先紧贴当前表情上方并水平居中，上方不足以完整容纳时改放在下方，最终位置限制在窗口可见范围内。保持按住并滑过其他表情时，预览图片和位置都跟随手指所在格更新，松手或取消手势立即关闭。预览不使用独立 Dialog，也不在 QQ 内重复实现 App 的导出、移动、删除和排序管理。
- 关闭按压预览只移除预览层并清除当前可见子项的按压态，不调用 `GridView.invalidateViews()`；取消预览不重新绑定整张网格，避免静态图和透明 GIF 同时重绘造成闪烁。

## 原文件缓存和 GIF

- `openFile` 返回的原始字节写入 QQ 私有缓存后再预览和发送，不转码、不抽首帧。
- 原文件由 `packId + itemId` 内容身份区分；itemId 是原图 MD5，表情顺序、封面或其他仓库 revision 变化不能使相同原图重复占用缓存。
- 原文件缓存上限 128 MiB；超过后按最近最少使用删除旧文件，当前正在预览或发送的文件受保护。
- QQ 进程的 Coil 解码内存缓存上限为 128 MiB，只缓存网格静态图；GIF 动画请求禁止写入该缓存，离屏时停止并释放动画解码状态。单元格绑定时先同步查询静态图缓存，命中后立即恢复 Drawable，显示不得等待原文件线程，文件租约随后异步补齐。
- 所有网格项目另有固定最大边 128 px 的首帧缓存：内存 LRU 上限 24 MiB，处理后 WebP 磁盘缓存上限 96 MiB。GIF 回屏时先同步显示首帧，再异步解码并替换为动画；静态图未命中高分辨率缓存时也使用首帧占位。首帧磁盘写入在独立单线程完成，不能阻塞可见图片队列。
- 静态图和 GIF 统一采用“静态预览 + 原文件”两级模型，不在仓库协议或 `index.jsonl` 增加缩略图字段。静态图原文件用于网格清晰显示，GIF 原文件用于可见时播放动画；预览图是可删除、可重建的软件缓存。
- 当前表情包条目加载后，后台预生成尚未浏览项目的全部 128 px 预览：前八行留给可见区高优先级任务，后台从其后按顺序处理，最后补齐首屏遗漏。预加载使用独立两个低优先级线程；切换表情包、页面回收或关闭面板时取消未开始任务。
- 全包预加载只通过 Provider 文件描述符读取并缩放首帧，不把完整原图复制进 QQ 原文件缓存，也不预解码完整 GIF。可见单元格仍单独按需取得原文件，因此预览任务不能冲掉 128 MiB 原文件 LRU。
- 中间预览格式使用 WebP。目标 Android 版本均原生支持 WebP 解码和透明通道；API 30 以后有透明通道的首帧编码为无损 WebP，不透明图使用质量 82 的有损 WebP，旧系统回退到质量 90 的兼容 WebP。AVIF 平台编解码保证过晚且小图解码成本更高，PNG 体积更大，原始 ARGB 磁盘占用过高。该选择只改变缓存效率，不改变显示协议。
- 预览、动画解码和发送通过显式文件租约持有缓存；任一租约未释放时淘汰器不得删除对应文件。不同文件的并发复制与淘汰使用同一活动集合和全局淘汰互斥。
- 释放租约只更新内存计数，不得在 QQ 主线程扫描缓存目录；淘汰请求由单线程后台合并执行。排序前固定文件的 mtime/length 快照，避免并发更新时间戳破坏比较器契约；后台清理异常只写日志，不能终止 QQ 进程。
- 缓存被清理后按需从 EmoRepo 重新读取，不影响仓库原文件。
- GIF 使用原文件时间轴和循环次数，支持 10 ms 帧；设备刷新率不足只允许跳过不可见帧，不能拉长完整循环。
- 图片离开可见区、预览关闭或面板销毁时停止动画并释放 Drawable。

## 发送

- 点击表情后先防重复点击，再从当前 Contact 快照构建 QQ NT `MsgElement`；普通会话使用 `createPicElement`，群频道使用 `createPicElementForGuild`。
- 发送通过 QQ 当前 `IKernelMsgService`，使用 QQ 生成的消息唯一 ID 和当前服务时间；不得通过分享 Intent 或模拟点击发送。
- 点击表情后立即关闭面板，不显示“正在发送”等 Toast；原文件缓存读取和 QQ 发送在后台继续，不能等待发送回调后才关闭面板。
- 只有 QQ 回调 `code == 0` 才算成功：成功后调用 `record_use(packId, itemId, usedAt)`。
- QQ 返回失败、原文件读取失败或抛出异常时只记录模块日志，不重新打开面板、不显示 Toast、不能记录使用，也不能自动重试，以免重复发送。
- `record_use` 失败只影响最近使用和同步，不回滚已经成功发送的 QQ 消息。
- 发送过程始终使用缓存中的原文件，因此 GIF、透明通道和静态图内容与仓库一致。

## 从 QQ 导入

- 图片消息原菜单保持不变，额外增加“添加到 EmoRepo”。
- 单图消息：选择目标表情包后显示文件数量和目标包二次确认，再写入。
- 混合消息或多图消息：提取全部图片，选择目标包后一次确认并批量导入；单张重复不阻塞其他图片。
- 优先使用 QQ 已缓存原图；没有原图时参考 QAux 保存链监听 `OidbSvcTrpcTcp.0x9067_202`，独立解析响应中的群聊/私聊 rkey。`/download` 地址使用 `multimedia.nt.qq.com + originImageUrl + 对应 rkey`，其他 QQ 相对地址使用 `gchat.qpic.cn`；rkey 尚未取得时明确报错，不发送缺少鉴权参数的猜测请求。
- Provider 使用现有仓库批量事务写入，返回成功、重复和失败数量；成功项完成落盘后再触发一次 Git 同步。
- 取消目标选择或二次确认时不读取大文件、不写仓库。

## 管理边界

- QQ 面板负责浏览、预览和发送，图片消息菜单负责导入。
- 删除、移动、封面和拖动排序仍在 EmoRepo App 完成；结果通过 revision 在下次打开或刷新 QQ 面板时生效。
- QQ 自带收藏表情的新增、删除和排序仍属于 QQ，不自动镜像到 EmoRepo，避免无法确定目标表情包或误把后台漫游同步当成用户操作。
- 首版不支持 TIM、QQ 国际版，也不复制 QAux 面板、发送桥或 Hook 实现。

## 验收

- QAux 禁用时，私聊、群聊中短按仍打开 QQ 面板，长按打开 EmoRepo 面板；重复进入聊天不会失效。
- 表情包和表情顺序与两个 `index.jsonl` 一致，四列网格、静态图、透明 GIF、有限循环和 100 FPS GIF 均正确。
- 抽屉首次以约 72% 屏高打开，向上翻找自动展开到约 92%；展开态下拉先收起，收起态再次下拉才关闭，表情网格未到顶部时不会误切换抽屉状态。
- 长按显示面板内预览：上方空间充足时位于表情上方，不足时位于下方；按住滑过其他格子时预览位置和内容跟随切换，松手立即关闭且不触发表情发送。
- 点击封面入口和左右滑动均能切包，选中入口、封面、名称和页面保持一致。
- “最近使用”始终位于第一项且顺序与合并后的设备 CSV 一致；删除或移动后不存在的记录不显示。App 中将列数从 3 到 8 逐项保存后，QQ 面板列数和单元格高度应在下次打开时对应变化。
- 冷缓存逐张出现且不阻塞主线程；热缓存二次打开不重复复制；超过上限后旧缓存淘汰且可重新读取。
- 在“可爱”等长表情包中滚动到底部再返回，静态图缓存命中时直接恢复；GIF 即使动画已释放也必须先出现首帧，不得显示空单元格。快速滚动产生的离屏任务应被取消，不能阻塞返回区域的可见项目。
- 选择长表情包后即使完全不滚动，后台也应逐步生成包内全部预览；完成日志中的 `total` 应等于启动时尚未缓存的条目数，`failed` 应为 `0`。预加载期间正常滚动不得出现比关闭预加载更明显的卡顿。
- 同一 QQ 进程内关闭后再次打开，首帧不得出现全局或当前包“正在读取”状态；后台 revision 校验不得清空未变化的网格。仓库、设置或最近使用变化后，后台结果应更新当前面板或下一次打开内容。
- 点击静态图或 GIF 后面板立即关闭且不显示 Toast；只有成功回调写最近使用，失败和快速连点不产生记录或重复消息。
- 单图、多图、包含重复项和取消确认分别完成真机导入验收。
- 切换聊天、关闭 Activity、QQ 重建输入栏、Provider 进程冷启动和缓存文件损坏均不得让 QQ 崩溃或发错会话。
- 源码检查、JVM 测试、Android 构建和 QQ 真机测试分别记录，不以构建成功替代运行时验收。

## 2026-08-28 实现与真机结果

- Review 后的高风险修复已落地：真实包通过 `writable=1` 暴露为 QQ 导入目标，虚拟最近包为只读；原文件缓存键移除全局 revision，并以 `CachedFileLease` 保护所有预览、动画和发送中的文件；发送回调增加 60 秒终止边界，确保租约最终释放。
- 租约首版在 `close()` 同步执行目录 LRU，展开/收起时多个 GIF 同时释放造成主线程卡顿；已改为后台合并淘汰。真机回归期间还捕获到可变 `lastModified()` 比较导致 TimSort 契约异常并终止 QQ，现已改为不可变文件快照排序并增加后台异常隔离。
- 修正版重新安装后，当前面板可见 35 个图片单元格且全部正常显示；连续两轮展开/收起采集 602 帧，现代 FrameMetrics 的 janky frames 为 `0`，50/90/95/99 分位分别为 `5/9/10/11 ms`，Missed Vsync、Slow UI thread、Slow bitmap upload 和 Slow issue draw 均为 `0`，日志没有缓存清理或图片加载异常。
- 高度动画仍会在结束时让 GridView 重绑并闪烁，因此最终方案改为：sheet 始终按 92% 高度测量，72% 收起态仅使用 `translationY`，底部表情包栏为独立固定覆盖层。连续两轮切换后仍有 40 个可见表情且无空白；882 帧中现代 janky frames 为 `2`（`0.23%`），50/90/95/99 分位为 `6/9/10/11 ms`，Missed Vsync 为 `0`，日志无缓存或图片加载错误。
- QQ 面板现在过滤真实空包并在表情包栏末尾显示齿轮“设置”。QQ 会拦截普通 Context `startActivity`，最终实现使用系统 PendingIntent 发送显式组件；真机由 QQ UID 成功启动 `top.e404.emorepo.dev/MainActivity`，并直接选中“软件设置”路由。
- QQ 会话 fallback 不再使用进程级 Contact 单值；SessionEntry 和图片消息 Contact 均绑定 Activity，点击表情按钮时优先解析同 Activity 的 ChatPie，会话销毁同步移除 fallback。

## 2026-08-29 长表情包滚动缓存回归

- “可爱”长包滚动后返回会重新逐张加载，定位到两项共同原因：解码内存 LRU 只有 12 MiB；网格离屏后只释放 Drawable，没有取消尚未开始的原文件任务，快速滚动会让新的可见请求排在过期 FIFO 任务后面。
- `CellState` 原先还是含可变 `disposable` 的 `data class`，写入哈希集合后修改字段会改变哈希值，导致回收时可能无法移除。现改为引用身份普通类，并保存可取消的 `Future`；回收和页面销毁同时取消任务、释放 Drawable 和文件租约。
- 首轮把解码 LRU 从 12 MiB 调到 64 MiB，并以自动滑动后约 350 ms 的截图作为通过依据；用户按实际节奏复测仍能看到上方表情重新加载，因此该结论作废，不能作为验收通过。
- 四列下 243 张约 270×270 的单帧 ARGB 基础像素已接近 68 MiB，“可爱”另有 89 张 GIF 的解码器和帧缓冲，64 MiB 会必然过早淘汰。第二版把 LRU 提高到 128 MiB，并增加真正的同步内存命中路径及释放时的 `memoryHits/memoryMisses/cacheBytes` 统计；真机结果需重新记录。
