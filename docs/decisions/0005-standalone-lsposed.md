# 独立 LSPosed QQ 适配

- 状态：`confirmed`
- 日期：2026-08-28

## 决策

- EmoRepo 本体同时作为独立 LSPosed 模块，只作用于 Android QQ 主进程。
- 不再要求 QAux 合并公共 Provider SPI，也不依赖 QAux 运行时。
- 仓库文件协议继续保持平台无关；QQ Hook、菜单、面板和发送属于 Android QQ 适配层。
- 图片消息原长按菜单保持不变，额外增加“添加到 EmoRepo”。
- QQ 适配通过受控 IPC 查询和修改 App 私有仓库，不直接访问私有路径，不在 QQ 进程运行 JGit。
- QAux 只作为 QQ 兼容性参考实现：允许参考其已经验证的特征字符串、包范围、结构条件和接口版本断点，但 EmoRepo 不依赖 QAux 运行时，也不复制其定位框架代码。
- QQ 内部类优先使用稳定名称；稳定名称失效时，由 EmoRepo 使用上游 DexKit 独立执行参考 QAux 规则形成的轻量定位目标，并在反射加载后再次校验结构。
- 定位结果按目标 ID、定位规则版本、QQ `versionCode` 和宿主 APK 指纹持久缓存；缓存命中仍需结构校验，校验失败立即丢弃并重新定位。
- 兼容分支以接口结构是否可用为依据，不按每个 QQ 版本分别实现；只有构造器、字段语义或消息组件模型真实变化时才增加结构适配器。
- 图片菜单组件按 QQ NT 组件包边界和基类结构识别，不写死包内可能随版本变化的具体类名。
- 定位在 QQ Application 建立后后台预热，不在每次长按菜单时扫描；多候选、无候选或定位异常时必须安全停用对应能力，不能使 QQ 崩溃。
- DexKit 运行在以系统类加载器为父级的独立 ClassLoader 中；APK 使用可提取的 JNI 打包方式，从 EmoRepo 自身的 `nativeLibraryDir` 加载匹配版本，避免 QQ 进程内其他 LSPosed 模块携带同包名、不同版本 DexKit 时发生类或 JNI 冲突。

## 分阶段实现

1. 图片消息菜单、表情包选择和真实导入。
2. 在 QQ 中提供独立 EmoRepo 表情面板并复用 QQ 发送能力。
3. 发送成功后的使用记录、删除和排序同步。
4. 参考 QAux 的定位规则逐个增加 EmoRepo 实际需要的轻量定位目标；首个目标为 QQ NT 图片菜单抽象类。

## 后果

- 不再承担 QAux 上游 PR 和公共 SPI 的维护成本。
- EmoRepo 自己承担 QQ 内部实现变化、LSPosed 兼容和真机回归。
- 不复制 QAux 的 Hook、定位框架、发送桥或 GPL 实现；需要的功能独立实现，DexKit 使用其上游公开依赖。
