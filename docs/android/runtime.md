## 存储

默认仓库位于 App 私有目录：

```text
<filesDir>/repository/
```

- 不默认申请公共存储权限。
- 导入和导出通过系统文件选择器完成。
- 预览转发通过只读 `FileProvider` URI 分享单个图片，并使用临时 URI 权限；不得把私有仓库路径或目录权限交给接收应用。
- Git 凭据不放在仓库目录。
- 私有仓库、配置和凭据全部排除在 Android 云备份和设备迁移之外，避免恢复出不完整的 Git 工作树或失效密钥引用。
- App 卸载会删除私有仓库，因此 UI 必须明确提示用户在卸载前导出或确认远端已同步；具体提示流程待 UI 文档确认。

## QQ 进程访问

EmoRepo LSPosed 适配代码运行在 QQ UID 下，不能直接访问上述私有目录。App 提供一个导出的受控 `ContentProvider`：

- `query` 分页返回表情包和表情元数据。
- `query` 同时提供 QQ 面板列数设置；表情包结果在根索引项前增加合并设备“最近使用”和动态“最近添加”虚拟包，虚拟项额外返回实际源表情包 ID。“最近添加”不落盘，由当前仓库记录时间和最近使用集合实时计算。
- `openFile` 返回图片的只读 `ParcelFileDescriptor`。
- `call(record_use)` 在 QQ 发送成功回调后追加本设备最近使用记录。
- `call(import_item)` 接收单个只读原图文件描述符；`call(import_items)` 接收最多 50 个文件描述符。两者按 64 MiB 单文件、256 MiB 批次总量逐项有界读取并导入，不能把整批文件同时读入内存。
- 表情包元数据明确返回是否允许写入；“最近使用”等虚拟包只读，QQ 导入目标不得展示或接受只读包。
- QQ 定位缓存调用只允许读写固定定位目标的类名、规则版本和宿主 APK 指纹；缓存位于 EmoRepo 私有配置，不进入 Git 仓库，也不向 QQ 暴露 App 私有路径。
- 每次调用校验 `Binder.getCallingUid()` 对应包名，只允许 EmoRepo 自身和受支持 QQ 包。
- 对 QQ 包进一步校验签名证书摘要，避免同包名伪装。
- 不向调用方暴露仓库绝对路径、Git 目录或 Token。
- Provider 不直接执行 Git 操作；最近使用写入完成后只按设置提交 WorkManager 同步任务。
- Provider 的只读元数据、图片路径和最近使用查询不得等待 Git 网络或本地写入阶段；读取不获取仓库写入锁，并在工作树暂时不可解析时回退到最近一次有效快照。
- 创建仓库访问对象不得获取仓库写入锁、执行事务恢复或打开 JGit 仓库。App 首屏可以在主线程创建轻量对象，但事务恢复、真实仓库校验和其他 Git 操作必须在 `Dispatchers.IO` 或 Provider/WorkManager 后台线程执行，主线程不得等待。

Manifest 已导出 Provider，查询、文件打开、导入、最近使用和定位缓存调用均先完成调用方校验。真机已验证 QQ UID 可读取和导入、shell UID 被拒绝；真实发送后的最近使用写入尚待验收。

## 2026-09-02 首屏 ANR 回归

- 系统 ANR 线程栈显示旧实现的 App 主线程在 `EmoticonRepository` 构造期间等待仓库内容锁；持锁后台线程正在 JGit `add` 中压缩对象，前台约 20 秒无法获得焦点。
- 仓库构造现只解析根路径并确认目录，不再取得写入锁；事务恢复延迟到首次真实仓库操作，并继续在同一写入锁内保证一致性。JVM 并发测试固定持有写入锁时，仓库构造仍在 1 秒内完成。
- `CPH2609` 保留 1.5 GiB 私有仓库覆盖安装后完成冷启动，仓库 9 个包和折叠字段均保留；同步网络请求持续失败期间 App 进程和首屏仍保持响应，未出现新的 ANR 或崩溃。

## 后台同步

- 立即同步使用唯一 OneTimeWorkRequest。
- 独立远端轮询使用唯一 PeriodicWorkRequest，默认 30 分钟，可配置或关闭；配置值不得低于 Android 的 15 分钟技术下限。
- 任务要求网络可用，不区分 Wi-Fi 和移动数据。
- WorkManager 只负责调度；仓库级互斥、恢复和幂等由同步层保证。
- App 进程被杀后，已提交但未 push 的提交必须由后续任务继续上传。
