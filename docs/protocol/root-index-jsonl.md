# 根目录 `index.jsonl`

- 状态：`verified`
- 更新：2026-08-30

## 目标和位置

仓库根目录使用一个受 Git 管理的 `index.jsonl` 控制表情包顺序。该顺序在 App 和 QQ Provider 中一致，并随仓库同步到其他设备；它不是仅限单台设备的私有配置。

```text
<repository>/index.jsonl
```

文件只负责表情包顺序，不保存封面、表情数量或其他当前没有用途的元数据。

## 编码和记录

- UTF-8，无 BOM。
- 一行一个完整 JSON 对象，不允许跨行格式化。
- 空行忽略。
- 文件末尾保留一个换行。
- 每行只允许 `name` 字段；未知字段属于协议错误。

```jsonl
{"name":"Kipfel"}
{"name":"chocolate"}
{"name":"何意味"}
```

| 字段 | 类型 | 必填 | 含义 |
|---|---|---:|---|
| `name` | string | 是 | 仓库根目录下的表情包目录名，也是合并主键 |

## 不变量

- `name` 必须符合表情包安全路径段规则，不能是 `recent`、`.git`、隐藏目录名或包含路径分隔符。
- 同一个 `name` 只能出现一次。
- 文件存在时，每个实际表情包目录必须恰好有一条记录；指向不存在目录的记录和没有记录的表情包目录都属于协议不一致。
- 根目录 `index.jsonl` 使用本文件的单字段结构；`<pack-name>/index.jsonl` 继续使用表情记录结构，解析器必须先按相对路径区分，不能只按文件名判断。
- JSONL 非空行的物理顺序是唯一表情包顺序；运行时不得按名称或其他字段二次排序。
- App、QQ Provider 和管理排序结果都使用这里的行序。

## 首次生成和兼容

- 已发布的旧根索引若全部带 `order`，首次读取时先按 `order, name` 恢复旧可见顺序，再原子移除字段；新旧记录混合时拒绝迁移。
历史仓库可能缺少该文件，因此缺失文件只作为初始化状态处理：

1. 读取时按表情包目录名的 Unicode 升序形成确定性临时顺序，保证旧仓库仍可打开。
2. 单纯读取不得修改仓库。
3. App 在第一次创建、删除或调整表情包顺序前，先按当前临时顺序原子生成根目录 `index.jsonl`，再完成本次操作。
4. 也提供显式“初始化表情包顺序”操作，使用户可以在不改动表情包的情况下生成文件并触发一次正常同步。
5. 文件一旦存在，损坏、缺项或多余记录都进入错误状态，不再退回目录名排序，也不得静默覆盖修复。

## 管理操作

- 创建表情包：把新记录追加到根索引末尾，并与新目录及其包内 `index.jsonl` 作为一次仓库事务落盘。
- 删除表情包：删除对应记录，并与目录删除作为一次仓库事务落盘。
- 调整表情包顺序：只重排完整 JSONL 行，不修改记录字段。
- 向包内导入、删除、移动或排序表情时不修改根目录 `index.jsonl`。
- 第一阶段仍不提供表情包改名；以后增加改名时必须同时修改记录主键和目录名。

## Git 冲突处理

以 `name` 做三方合并主键：

| 情况 | 结果 |
|---|---|
| 两边新增不同表情包 | 取并集 |
| 一边删除表情包，另一边未改顺序 | 删除记录 |
| 一边删除表情包，另一边修改顺序 | 保留仍实际存在的目录；目录已删除则删除记录并记警告 |
| 同一批已有表情包两边都调整行序 | 本地行序优先 |
| 远端独立新增表情包 | 按远端相邻记录插入本地行序 |

合并完成后必须与实际表情包目录集合核对；无法确定目录增删结果、文件不可解析或仍不能形成一一对应关系时停止自动合并并报告用户。

## 持久化

- 使用根目录临时文件、刷新并原子替换。
- 表情包创建或删除涉及根目录 `index.jsonl`、目录和包内 `index.jsonl`，必须纳入管理事务日志，不能只保证单文件原子性。
- Provider 只读取已经落盘的一致快照，不负责补写或修复排序文件。

## 验收

- 缺失文件时旧仓库仍按确定性的目录名顺序显示，且读取不产生工作树修改。
- 初始化后重复序列化得到逐字节一致内容。
- 重复名称、未知字段、不安全名称、缺项和多余记录均能检测。
- 创建、删除和调整顺序后，目录集合与排序记录保持一一对应。
- QQ Provider 返回顺序与根索引行序完全一致。
- 两端独立新增表情包可以自动合并；已有包并发排序冲突按本地行序优先。
