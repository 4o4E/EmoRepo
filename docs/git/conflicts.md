# Git 冲突处理

- 状态：`confirmed`
- 更新：2026-08-25

## 原则

- 能根据协议确定结果的冲突自动处理。
- 自动处理必须保留可解释日志。
- 不能可靠判断或可能丢数据时才通知用户。
- 不把 Git 冲突标记交给 JSONL/CSV 解析器继续运行。

## `index.jsonl` 规则

仓库根目录 `index.jsonl` 先按 `name` 合并表情包顺序；表情包目录内的 `index.jsonl` 再按 `md5` 合并表情记录。解析器必须按相对路径区分两者。

根索引规则：

- 两边新增不同表情包时取并集。
- 已有表情包发生并发行序调整时本地行序优先。
- 远端独立新增记录按远端最近的前后锚点插入本地序列，不改写已有记录字段。
- rebase 完成后根索引必须与实际表情包目录一一对应，否则停止同步并报告用户。

包内索引规则：

以 `md5` 做三方合并主键：

| 情况 | 提议结果 |
|---|---|
| 两边新增不同 `md5` | 取并集 |
| 一边删除，另一边未改 | 删除 |
| 一边删除，另一边修改 | 保留修改，记录警告 |
| 同一记录修改不同字段 | 字段级合并 |
| 同一记录两边修改 `time` | 取较大值 |
| 已有记录两边调整行序 | 本地行序优先 |
| 远端独立新增记录 | 按远端相邻记录插入本地序列 |
| 合并后多个 `icon: true` | 本地明确修改优先，否则取最终行序第一项 |

## CSV

- 以 `(package, name)` 合并。
- `time` 取最大值。
- 重新稳定排序和序列化。

## 图片

- 正常图片名由内容 MD5 决定，不同内容应得到不同路径。
- 同一路径图片字节不同属于协议损坏，不自动选择一侧。

## 必须报告用户

- JSONL 或 CSV 无法解析。
- 同一 `md5` 对应不同图片字节。
- 非协议文件出现二进制冲突。
- 远端历史被改写，正常 rebase 无法继续。
- 自动处理达到重试上限仍无法形成干净索引。
