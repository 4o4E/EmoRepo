# 诊断日志

- 状态：`verified`
- 更新：2026-09-01

## 目标和范围

- App 主进程、WorkManager 同步任务、仓库管理、ContentProvider IPC 和 QQ Hook 都写入同一套结构化诊断日志。
- 日志同时写入 Android `logcat` 和 App 私有目录 `files/logs`；日志目录不属于表情 Git 仓库，不参与同步。
- 每条日志包含 ISO-8601 时间、级别、进程、线程、组件、事件名、结果和必要的耗时/数量；异常保留完整类型、cause 链和堆栈。
- 不记录图片字节、QQ 聊天内容、消息正文、联系人、群号、账号/会话标识、Git Token、认证头、作者邮箱或系统选择器返回的外部 URI；这些与组件诊断无关的数据不得为了“完整日志”而采集。
- 远端地址只允许记录移除用户名、密码、查询参数和片段后的 HTTPS 地址；异常和堆栈写入前必须再次按当前 Token 和常见凭据形式脱敏。

QQ Hook 运行在 QQ 进程，不能直接写 App 私有文件。Hook 日志继续写入 LSPosed 日志，同时通过现有受控 ContentProvider 发送给 EmoRepo；Provider 只接受已验证的 QQ 调用方，单条消息和堆栈长度受限，避免日志注入耗尽存储。

## 文件和轮转

- 当前文件为 `emorepo.log`，UTF-8 JSONL，一行一个完整事件，多行堆栈按 JSON 字符串转义。
- 单文件达到 2 MiB 后轮转，保留当前文件和 4 个历史文件，总量不超过约 10 MiB。
- 写入串行化；每条事件完成后关闭或刷新文件，日志失败不得中断原业务，并回退到 `logcat` 报告一次。
- App 进程未捕获异常在交给原处理器前写入文件；主动捕获的异常不得只记录最外层包装消息。

## 同步日志和陈旧锁恢复

同步使用稳定的运行 ID 串联以下阶段：

```text
调度 → 读取配置 → 仓库预检 → 暂存 → 提交 → fetch → rebase → 协议校验 → push → 完成
```

- 每一阶段记录开始、成功、跳过、重试或失败以及耗时，不记录 Token。
- 同步失败时，设置页展示“阶段 + 最具体的已脱敏 cause”，文件日志保留完整 cause 链和堆栈。
- 进入 JGit 前已经持有 EmoRepo 仓库独占锁；若仓库状态为 `SAFE`、现有 `index` 可读取且发现 `.git/index.lock`，则该锁不可能属于另一个 EmoRepo 同步，记录警告后删除陈旧锁并继续。
- 仓库状态不安全或索引不可读取时不得自动删除锁，必须停止并保留现场。
- 不自动删除 `.git/objects` 中的未知临时文件；它们不阻止同步，后续只能由明确的 Git 清理流程处理。

## 导出

- 设置页提供“导出诊断日志”，通过系统文件创建器写出 `EmoRepo-diagnostics-<时间>.zip`。
- ZIP 包含当前及轮转日志和 `diagnostics.json`；后者只包含日志协议版本、App 版本、Android 版本、设备型号、导出时间、同步状态、Git 分支/HEAD、仓库状态以及锁文件是否存在。
- ZIP 不包含设置 XML、Token、表情索引、图片、最近使用记录或 Git 对象。
- 导出前生成日志文件快照，导出失败或取消不修改现有日志。
