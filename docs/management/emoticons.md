# 表情管理

- 状态：`confirmed`
- 更新：2026-09-02

## 已确认能力

- 创建表情包。
- 重命名和删除表情包。
- 初始化和调整根目录 `index.jsonl` 中的表情包顺序。
- 从系统文件选择器导入一个或多个图片。
- 向指定表情包新增表情。
- 删除单个或批量选中的表情。
- 把单个或批量选中的表情移动到其他表情包。
- 设置或清空表情包封面。
- 修改顺序；最终结果直接写成 JSONL 行序。
- 所有成功修改都进入 `git/sync.md` 的表情修改触发器。

表情包名称就是仓库目录名。第一版不继续使用 lite-tools 的 `sticker.json` 标题覆盖机制。

缺少根目录 `index.jsonl` 的旧仓库只读时按目录名形成临时顺序；首次创建表情包前写入当前顺序，新包追加到末尾。根索引存在后，App 和 QQ Provider 都使用其行序。

## 导入

- 通过内容识别图片类型，不信任来源文件扩展名。
- 支持 `png`、`jpg`、`jpeg`、`gif`、`webp`。
- 文件以 `<md5>.<ext>` 写入目标表情包，索引和图片必须作为一次仓库事务更新。
- JPEG 导入统一使用 `jpg` 扩展名；已有合法 `jpeg` 记录仍可读取。
- 单次选择多张图片属于批量导入，并返回逐项成功、重复或失败结果。
- App 和 QQ 单批最多接收 50 张；单文件最多 64 MiB，批次累计原始字节最多 256 MiB。读取和内容识别逐项执行，内存中不得同时保留整批原图，也不得额外复制完整字节数组。

## 删除和移动

- 删除前显示选中数量并要求确认。
- 移动保留 `md5`、`time` 和图片字节；不存在重复项时插入目标索引第一行。
- 目标包已经存在相同 `md5` 时视为去重后的移动成功：保留目标记录当前行位置、`time` 和 `icon`，删除来源图片和来源索引记录。
- 原表情是显式封面时，移动后原包进入无显式封面状态，不自动把封面标记移到目标包。
- 批量操作必须返回逐项结果，不能只返回一个布尔值。
- 批量操作按 lite-tools 行为逐项执行；部分失败时保留已成功项目，并展示成功与失败数量及失败原因。
- 删除时只移除本设备最近使用 CSV 中的对应记录，其他设备文件不由本设备改写。
- 移动时同步更新本设备最近使用 CSV 中的包名，其他设备文件保持不变。

## 表情包重命名和删除

- 重命名同时修改目录名和根索引中同一位置的 `name`，保留 `collapsed`、包内索引、图片字节和行序；目标名称必须是安全且未占用的表情包名称。
- 重命名同步修改所有 `recent/*.csv` 中引用该包的 `package`，避免其他设备记录失效；操作成功后只触发一次 Git 同步。
- 删除先二次确认包名和表情数量，再从根索引移除记录并删除整个表情包目录；同时移除所有设备最近使用文件中对该包的记录。
- 重命名和删除均使用同一仓库锁，并通过同目录暂存名称完成回滚；任一步失败必须恢复目录、根索引和最近使用文件。

## 包内草稿编辑

- 编辑草稿记录进入编辑时的完整 MD5 行序、待删除集合和当前选择；删除、移动到开头只修改草稿。
- 移动到开头保持所选表情之间的原相对顺序，也保持未选表情之间的原相对顺序。
- 完成时校验仓库仍与进入编辑时的 MD5 集合一致；外部变化时拒绝覆盖并要求重新进入编辑。
- 完成操作一次性写最终索引、删除待删除图片并更新本设备最近使用；任一步失败恢复原索引和图片。

## 缩略图

- 缩略图只属于 App 缓存，不写入表情 Git 仓库或 `index.jsonl`。
- 保持原始宽高比，不拉伸。
- 缩小和显示都必须启用双线性或更高质量插值过滤，禁止最近邻缩放，避免边缘锯齿。
- GIF 在表情包封面、表情包管理网格和大图预览中自动循环播放；动态 WebP 仍可使用静态首帧缩略图。
- 缓存键至少包含图片 MD5 和目标尺寸，原图变化后不得复用旧缩略图。
- 表情包页面立即显示，不等待整包或首屏全部预加载完成。
- 静态图和 GIF 首帧使用 256px 磁盘缩略图缓存，位于 App `cacheDir`；写入采用临时文件后原子替换。
- App 磁盘缩略图使用无损中间编码并保留透明通道，不能因有损缓存产生偏色、发黄或透明边缘污染。编码策略变化时必须提升缓存目录版本，让旧缩略图自然失效并按需重建。
- 磁盘缩略图缓存超过 256 MiB 时按最近最少使用顺序清理到 224 MiB；只删除可重新生成的缓存，不删除仓库原图。
- 缩略图内存缓存按估算像素字节计量，上限 12 MiB，超过后清理到 10 MiB；全屏大图不进入该缓存。
- 动画解码器使用独立的 12 MiB 内存缓存预算；只为当前可见 GIF 保持动画，离屏后停止并释放。
- 不同图片最多并行解码 4 个；同一 MD5 和尺寸的并发请求合并，避免重复解码。
- Android 28 及以上优先使用平台 `AnimatedImageDecoder`，Android 24 至 27 使用兼容 GIF 解码器。

### 2026-09-02 缩略图颜色回归

- 旧 `emoticon-thumbnails-v1` 对透明 PNG 使用质量 90 的有损 WebP，真机样本 `dc3170892782d9da776b96952d8b2132.png` 的透明背景出现白色块状污染。
- App 缓存升级为 `emoticon-thumbnails-v2`；Android 30 及以上使用无损 WebP，旧系统使用 PNG。相同样本重新生成后透明背景和原色保持正常，旧 v1 文件不再参与读取。

## 连续拖动选择

- 普通模式不显示多选框，点击右上角“编辑”后才进入草稿编辑状态并显示全部多选框。
- 编辑状态下点击表情卡片或多选框切换单项选择；点击“完成”提交草稿，顶部返回或系统返回丢弃草稿并退出。
- 从某个多选框长按后拖动才进入连续选择；长按成立前的普通纵向手势交给列表滚动，不能被选择手势提前消费。普通模式点击图片仍打开预览。
- 选择区间以当前 JSONL 行序对应的视觉顺序计算，即从左到右、从上到下。
- 起点到当前终点之间的全部表情加入选择；反向拖动使用同一规则。
- 拖动只增加区间选择，不取消拖动开始前已经选中的其他表情。
- 抬手后结束本次拖动；拖动期间不触发表情预览。
