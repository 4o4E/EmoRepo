# 管理操作持久化

- 状态：`confirmed`
- 更新：2026-08-31

## 当前阶段

- 同一 App 进程内，仓库管理操作使用仓库级互斥，不并发改写同一索引。
- `index.jsonl` 和新图片先写同目录临时文件，刷新到存储后再替换目标文件。
- 替换过程保留短期备份；下次读取或写入前自动完成或恢复中断的单文件替换。
- 操作失败时执行补偿：恢复已修改索引并删除本次新建文件。
- 成功返回前重新读取涉及的索引，确保落盘内容仍可按协议解析。
- 表情包重命名/删除和包内草稿完成使用可恢复的同目录暂存目录；根索引、包内索引、图片和最近使用更新全部成功后，通过同目录原子改名标记提交，再异步式清理提交残留。提交前失败或中断按原路径恢复，提交后的清理残留只能清理、不得回滚。

## 尚未实现

进程在两个文件替换之间被强制终止时，跨图片和多个 `index.jsonl` 的恢复需要独立事务日志。该日志与 Git 同步互斥一起实现；在此之前管理服务不得标记为完整运行时实现。
